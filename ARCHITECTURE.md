# Architecture

**How it works.** The bot is a LiveKit Agents worker running a pipeline: Deepgram `nova-3` streams the clinic agent's speech into text, OpenAI `gpt-4o-mini` decides what the patient says next, and Cartesia `sonic-2` speaks it back, with Silero voice activity detection and LiveKit's turn detector model deciding when the clinic has finished talking. `run.py` places each call by creating a LiveKit room, dispatching the patient agent into it, and dialing +1-805-439-8008 through a LiveKit outbound SIP trunk connected to a Twilio Elastic SIP trunk. The clinic joins the room as a normal participant, so the agent treats a phone call exactly like any other conversation. Each scenario is a small JSON file (context, goal, twist) layered on a shared patient persona and turned into the bot's instructions, so adding a test means adding a file, not writing code. A hidden recorder participant subscribes to both audio tracks, mixes them on one shared clock, and stamps each transcript line with the moment that speech started, so every timestamp in a transcript lines up with the recording. When the clinic hangs up, `run.py` deletes the room, which ends the job and saves the OGG file through ffmpeg.

**Why I built it this way.** Latency was the constraint behind almost every choice, because a caller that pauses for 3 seconds before every reply doesn't sound like a person and makes the clinic agent behave differently. Every stage streams, the LLM is small, and the TTS is built for fast first audio, which kept time to first token between 0.53 and 1.31 seconds and total response time around 1.5 to 2.0 seconds on the LiveKit dashboard. Turn taking took the most iteration. My first calls showed the bot answering "Okay" into every "one moment, let me check" pause, so the bot now cancels its reply whenever the clinic's last sentence is a hold phrase rather than a question, and LiveKit's turn detector (which reads the words, not just silence) keeps it from jumping in when the clinic pauses mid sentence. The bot also needed rules a real caller follows without thinking: an `end_call` tool that refuses to hang up before 60 seconds, a nudge to wrap up at 2:00, and a hard hangup at 2:55. The biggest tradeoff is that scenarios run in order against shared demo data, so later calls see what earlier calls changed. That makes the tests realistic, and it's how the duplicate patient record bug surfaced, but it also means a scenario's written context can go stale, which is why the cancel scenario was rewritten to not assume a specific date.

## Choices and tradeoffs

| Decision | Choice | Why | Alternative I passed on |
|---|---|---|---|
| Speech to text | Deepgram `nova-3`, streaming | Low latency on 8 kHz phone audio, plus keyterm prompting. Without it, "Lukowski" came back 7 different ways in early calls. | Whisper: strong accuracy, but it isn't built for streaming, so every reply would wait on a full transcription |
| LLM | OpenAI `gpt-4o-mini`, temperature 0.8 | Playing a patient needs quick, natural replies more than deep reasoning. Fast first token, low cost, and reliable tool calling for `end_call`. Temperature 0.8 keeps phrasing varied across calls. | `gpt-4o`: better reasoning the role doesn't need, at noticeably higher latency and cost |
| Text to speech | Cartesia `sonic-2` | Very fast time to first audio and a natural voice that handles fillers like "um." | ElevenLabs: excellent voices, but slower and more expensive per call |
| Turn detection | Silero VAD plus LiveKit turn detector, plus a hold phrase rule | VAD alone treats every pause as the end of a turn. The turn detector reads the words, and the hold phrase rule covers the "one moment" case it still missed. | Silence timeout only: simpler, but talked over the clinic constantly |
| Phone connection | LiveKit outbound SIP trunk to Twilio Elastic SIP | The call lands in the LiveKit room as a participant, so there's no audio plumbing to write. Twilio's Ashburn termination and LiveKit's US Central region keep the media path short. | Twilio Media Streams over a websocket: works, but means hand writing audio encoding and buffering |
| Recording | Custom hidden recorder participant | Mixes both sides on the same clock the transcript uses, so timestamps match the audio exactly. | LiveKit Egress: less code, but separate setup and cost, and its timeline wouldn't match my transcript timestamps |
| Test design | JSON scenarios on a shared persona, run in order | New tests without code changes, and realistic carryover between calls. | Independent scenarios with fresh demo data each time: cleaner, but the demo line has no reset, and it would miss bugs that only show up across calls |
